## 二、P0-1 重连退避

### 2.1 算法

**Exponential + full jitter**(AWS 经典):
```
delay_n = uniform(0, min(base * factor^n, max))
```
- `base = 0.5` 秒,`factor = 2.0`,`max = 30.0` 秒
- `_connect_fail_count` 单调递增,`n` 取该值;连接成功后重置 0
- jitter 用 `random.uniform`,与库现有依赖一致(标准库)

### 2.2 物理形态:时间戳门控(零 sleep)

**守门位置:`connect()` 入口**(`base_client.py:106`)。公开调用与 `_execute` 惰性重连(锁内)走同一入口,一处守门两路径全覆盖。零 sleep 设计使锁内守门仅是一次时间戳比较,无阻塞代价。

```python
class BaseClient:
    def connect(self) -> bool:
        with self._lock:
            now = time.monotonic()
            if self._reconnect_backoff and now < self._next_connect_at:
                delay = self._next_connect_at - now
                self._set_error("连接退避中:%.1f 秒后允许重连" % delay,
                                ErrorCategory.TRANSPORT, None)
                return False          # 与现有 connect 失败契约一致:置 last_error 返回
            try:
                self._transport.connect(...)
                self._after_connect()
                self._connected = True
                self._next_connect_at = 0.0   # 成功 → 门控与计数全重置
                self._connect_fail_count = 0
                self._clear_error()
                return True
            except Exception as exc:          # 连接序列任何异常一律进入退避
                attempt = self._connect_fail_count
                cap = min(0.5 * (2.0 ** attempt), 30.0)
                self._next_connect_at = time.monotonic() + random.uniform(0.0, cap)
                self._connect_fail_count += 1
                self._set_error(_describe(exc), _categorize(exc), _extract_code(exc))
                return False
```

**关键设计**:
- **零 sleep**:不阻塞调用线程、不放大 RLock 持锁时间、不占用 aio executor 线程
- **失败契约与现状一致**:connect 失败置 `last_error` 三件套返回 False,读/写照现有惰性路径返回 `(False, None)` / False
- **单调时钟**:`time.monotonic()`,不受系统时间调整影响
- **运行中可关**:`client.reconnect_backoff = False` 即时跳过门控(每次连接时活读标志)

### 2.3 API 表面(与 retries/write_retries 同款)

```python
class BaseClient:
    def __init__(self, ip_address: str = "", port: int = 0) -> None:
        ...
        self._reconnect_backoff: bool = True       # 默认开
        self._next_connect_at: float = 0.0         # monotonic 时间戳
        self._connect_fail_count: int = 0

    @property
    def reconnect_backoff(self) -> bool:
        """连接失败后的指数退避门控(默认开)。断电/网线松动时防止高频重连风暴。"""
        ...

    @reconnect_backoff.setter
    def reconnect_backoff(self, enabled: bool) -> None:
        ...  # bool 校验,同 retries.setter 风格

    @property
    def next_connect_in(self) -> Optional[float]:
        """距下次允许 connect 的剩余秒数;None = 无门控,可立即连接。"""
        # 门控未启用或 _next_connect_at <= now → None;否则剩余 >0 秒
```

### 2.4 状态生命周期

| 事件 | `_next_connect_at` | `_connect_fail_count` |
|---|---|---|
| 初始化 | `0.0` | `0` |
| `connect()` 成功 | `0.0` | `0`(全重置) |
| `connect()` 失败(连接序列任何异常,含 `_after_connect` 握手失败) | `now + uniform(0, cap)` | `+1` |
| 门控命中(未到允许时间) | 不变 | 不变 |
| `disconnect()` / `__exit__()` | `0.0` | `0`(全重置) |
| 运行中置 `reconnect_backoff = False` | 字段保留但不参与判定 | 保留 |

### 2.5 aio 镜像

`ABaseClient` 增加 property + setter 转发(与 `retries` 转发同款,`aio/__init__.py:239-254` 风格):
```python

@reconnect_backoff.setter

@property

```

## 三、P0-2 错误结构化

### 3.1 ErrorCategory 枚举

**新增**(`src/omniplc/core/errors.py`):
```python
class ErrorCategory(enum.Enum):
    TRANSPORT = "transport"   # OSError(ConnectionRefused/Reset/DNS 等)、TransportClosedError
    PROTOCOL = "protocol"     # ProtocolFrameError(坏帧/校验错/格式不符)
    DEVICE = "device"         # DeviceError(PLC 自身报错,code 为协议原始码)
    TIMEOUT = "timeout"       # socket.timeout、TransportTimeoutError(链路完好,不断线)
    UNKNOWN = "unknown"       # 其他(含裸 OmniPLCInternalError 兜底)
```

### 3.2 分类映射(单一规则表,顺序敏感)

```python
# 注意顺序:TransportTimeoutError 是 DeviceError 子类,必须先判
_CATEGORIZE = [
    (TransportTimeoutError,          ErrorCategory.TIMEOUT),
    (socket.timeout,                 ErrorCategory.TIMEOUT),
    (ProtocolFrameError,             ErrorCategory.PROTOCOL),
    (DeviceError,                    ErrorCategory.DEVICE),
    (ConnectionRefusedError,         ErrorCategory.TRANSPORT),
    (ConnectionResetError,           ErrorCategory.TRANSPORT),
    (socket.gaierror,                ErrorCategory.TRANSPORT),
    (OSError,                        ErrorCategory.TRANSPORT),   # 其余网络错误兜底
    (TransportClosedError,           ErrorCategory.TRANSPORT),
]
# 兜底:未命中(含裸 OmniPLCInternalError、意外异常)→ UNKNOWN
```

`_categorize_exception(exc) -> ErrorCategory` 助手按表 `isinstance` 短路;**新增异常类型时必须同步维护本表**(见 §8 风险表)。

### 3.3 code 提取

```python
def _extract_code(exc: BaseException) -> Optional[int]:
    if isinstance(exc, DeviceError):
        return exc.code          # MC 结束码 / FINS 结束码 / Modbus 异常码等
    if isinstance(exc, OSError):
        return exc.errno
    return None                  # ProtocolFrameError / UNKNOWN / 成功 → None
```

### 3.4 新增 property

```python
class BaseClient:
    @property
    def last_error_category(self) -> Optional[ErrorCategory]: ...
    @property
    def last_error_code(self) -> Optional[int]: ...
```

### 3.5 写入点

统一经 `_set_error(msg, category, code)` / `_clear_error()` 内部助手(加锁,与现有 `_last_error` 同步写),替换现有零散的 `self._last_error = ...` 赋值点:

| 位置 | 写入内容 |
|---|---|
| `connect()` 失败(含门控命中) | msg + category + code |
| `connect()` 成功 | 三字段全清 None |
| `_after_connect()` 失败 | msg + category + code |
| `disconnect()` 失败 | msg + category + code |
| `_execute` 失败 `DeviceError` | category=DEVICE,code=exc.code |
| `_execute` 失败 `OSError/Internal` | 按 §3.2 表分类 |
| `_execute` 事务成功(读或写) | 三字段全清 None(与现有 `_last_error` 清空同步) |
| `_mark_disconnected()` | 不设(由 `_execute` 设过) |

**`last_error: Optional[str]` 契约不变**——旧调用方零感知;两个新 property 是纯增量。

### 3.6 aio 镜像

两个新 property 转发到 `self._sync`(只读,无 setter)。

### 3.7 README 示例

## 四、P0-3 写前原值采集

### 4.1 API 表面

```python
class BaseClient:
    def __init__(self, ...):
        ...
        self.read_before_write: bool = False   # 公开实例属性,运行时可切换

    self._last_write_prev: Optional[Tuple[str, Any]] = None

    @property
    def last_write_previous(self) -> Optional[Tuple[str, Any]]:
        """read_before_write 开启后,最近一次成功写入前的 (地址, 旧值) 快照。
        仅在「写前读成功 且 写入成功」时更新;其余情况保持上次值;初始 None。"""
```

### 4.2 行为

- `read_before_write = False`(默认)→ 完全等同 v0.33.0 行为,**零额外读线**
- `read_before_write = True` → 每个 `write_*` 调用前先 `read_*` 同地址;**读成功且写成功**时把 `(addr, prev)` 存入 `last_write_previous`
- **写前读失败**:write 照常执行(写优先级高,采集是附赠),快照**不更新**,不污染 `last_error`(读失败本身会经既有路径进 last_error,但 write 结果以写操作为准)
- **写失败**:快照不更新
- **类型化方法全覆盖**:`write_bool`/`write_short`/`write_ushort`/`write_long`/`write_ulong`/`write_float`/`write_double`/`write_string`
- **`write_many`**(基类批量写,已核实存在):开关开启时逐点先读,快照记录最后一个点;全栈审计由调用方自维护
- **MX `write_batch`**:同规则
- 快照是**单槽**(非历史环)——审计历史由调用方在每次写后取走自存(见 §4.5)

### 4.3 实现路径

`base_client.py` 在类型化 `write_*` 公共路径上加包装:

```python
def _write_with_prev_capture(self, addr, value, write_callable):
    captured: bool = False
    prev: Any = None
    if self.read_before_write:
        try:
            ok, prev = self._read(addr)   # 复用既有读路径(含类型推断)
            captured = ok                 # 仅读成功才标记
        except (DeviceError, OSError, OmniPLCInternalError):
            captured = False              # 吞例外,不污染 last_error
    ok = write_callable()
    if ok and captured:                   # 读成功 + 写成功才更新
        self._last_write_prev = (addr, prev)
    return ok
```

各类型化 `write_*` 方法体改为经此包装调用原写逻辑。**门控与锁**:读+写在同一 `_lock` 事务内串行,与现有一致。

### 4.4 aio 镜像

- `read_before_write`:property + setter 转发(aio 侧不能暴露裸属性,写操作需落到同步实例)
- `last_write_previous`:只读 property 转发

### 4.5 README 示例

```python
# 单次审计
client.read_before_write = True
client.write_ushort("D100", 42)
addr, prev = client.last_write_previous
logger.info("%s: %s -> 42", addr, prev)

# 持续审计(调用方自存历史)
history = []
client.read_before_write = True
client.write_float("D200", 3.14)
history.append((*client.last_write_previous, 3.14, time.time()))

# 关闭恢复零开销
client.read_before_write = False
```

## 六、明确不做(用户裁决)

| 不做项 | 原因 |
|---|---|
| `read_before_write` 的**每次调用参数版**(`write_*(..., read_before=True)`) | 用户裁决"属性开关"而非"参数开关" |
| `client.transaction()` 上下文管理器 | 所有 write 隐式多读线,违反尊重现场实时性;read+write 不原子 |
| `write_history` 环形历史 | 快照单槽 + 调用方自存,更灵活 |
| `compare_and_swap` 协议级 CAS 扩充 | 留 backlog,本版不动 |
| `stats` 加"上次错误至今"字段 | stats 已有 timestamps,够用 |
| 异步原生 asyncio 重写 | 架构改造,留 v1.x |
| ConnectionRefused/Reset/Timeout 细分到 `last_error_category` | 用户裁决 5 值粒度够用(细分在 TRANSPORT 内部,README 可用 `errno` 补充) |
| `last_error_history` 错误环 | 库只暴露 latest |
| 熔断器(连续 N 次失败短时拒绝) | 与退避功能重叠,退避已控风暴;留 backlog |

## 八、风险与回退

### 风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| `reconnect_backoff=True` 默认开,老用户感知行为变化 | 中 | 低 | README 显著标注;`client.reconnect_backoff = False` 一行恢复 |
| 新增异常类型绕过 §3.2 规则表 | 中 | 低 | 兜底 UNKNOWN;errors.py 头部注释"新增异常必同步规则表";§5.1 有逐行短路序测试 |
| `read_before_write=True` 被误开 → 总线负载翻倍 | 低 | 中 | 默认 False;命名即语义;文档标注成本 |
| 门控状态字段在异常路径漏重置 | 低 | 中 | §2.4 生命周期表逐项对应测试;`disconnect()` 全重置兜底 |

### 回退方案

- `client.reconnect_backoff = False` → 完全 v0.33.0 行为
- `client.read_before_write` 保持/设为 False → 零开销
- `last_error` 未变 → 旧调用零感知
- 极端情况整体 revert 单 commit 即可(无跨模块耦合)
