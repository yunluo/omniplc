## 二、P0-1 重连退避

### 2.1 算法

**Exponential + full jitter**(AWS 经典):
```
delay_n = uniform(0, min(base * factor^n, max))
```
- `base = 0.5` 秒
- `factor = 2.0`
- `max = 30.0` 秒
- `_connect_fail_count` 单调递增,`n` 取该值;成功后重置 0

### 2.2 物理形态:时间戳门控(零 sleep)

```python
class BaseClient:
    def _connect(self) -> None:
        now = time.monotonic()
        if self._reconnect_backoff and now < self._next_connect_at:
            delay = self._next_connect_at - now
            raise TransportClosedError(f"连接退避中:{delay:.1f}s 后允许")
        try:
            self._transport.connect(...)
            self._after_connect()
            self._next_connect_at = 0.0
        except (OSError, OmniPLCInternalError) as exc:
            attempt = self._connect_fail_count
            cap = min(self._RECONNECT_BASE * (self._RECONNECT_FACTOR ** attempt),
                      self._RECONNECT_MAX)
            self._next_connect_at = now + random.uniform(0.0, cap)
            self._connect_fail_count += 1
            raise
```

**关键设计**:
- 守门位置:`_connect()` 入口,在 RLock 持锁之前
- **零 sleep**:不阻塞调用线程、不阻塞 RLock 持锁者、不阻塞 aio executor 线程
- **状态单调**:`time.monotonic()`,不受系统时间调整影响

### 2.3 API 表面

**新增类属性**(`BaseClient`):
```python
class BaseClient:
    DEFAULT_RECONNECT_BACKOFF: bool = True
    _RECONNECT_BASE: float = 0.5
    _RECONNECT_FACTOR: float = 2.0
    _RECONNECT_MAX: float = 30.0
```

**构造参数**:
```python
def __init__(self, ..., reconnect_backoff: bool = DEFAULT_RECONNECT_BACKOFF):
    self._reconnect_backoff = reconnect_backoff
```

**新增只读属性**:
```python
@property
def reconnect_backoff(self) -> bool: ...
@property
def next_connect_in(self) -> Optional[float]:
    """距离下次允许 connect 的剩余秒数;None 表示无门控可立即连"""
    ...
```

### 2.4 状态生命周期

| 事件 | `_next_connect_at` | `_connect_fail_count` |
|---|---|---|
| 初始化 | `0.0` | `0` |
| `_connect()` 成功 | `0.0` | `0`(重置) |
| `_connect()` 失败(OSError/Internal) | `now + uniform(0, cap)` | `+1` |
| `_connect()` 失败(DeviceError, 不应到此) | 不变 | 不变 |
| `disconnect()` / `__exit__()` | `0.0` | `0`(重置) |
| `reconnect_backoff = False` | 不参与 | 不参与 |

### 2.5 aio 镜像

`ABaseClient` 增加两个 property 转发:
```python
@property
def reconnect_backoff(self) -> bool: return self._sync.reconnect_backoff
@property
def next_connect_in(self) -> Optional[float]: return self._sync.next_connect_in
```
`_run(self._sync.connect)` 经 gate 自然短路,零额外代码。

## 三、P0-2 错误结构化

### 3.1 ErrorCategory 枚举

**新增**(`src/omniplc/core/errors.py`):
```python
class ErrorCategory(enum.Enum):
    TRANSPORT = "transport"   # OSError ConnectionRefused/Reset/DNS,TransportClosedError
    PROTOCOL = "protocol"     # ProtocolFrameError(坏帧/校验错/格式不符)
    DEVICE = "device"         # DeviceError(code 存在,PLC 自身报错)
    TIMEOUT = "timeout"       # socket.timeout, TransportTimeoutError
    UNKNOWN = "unknown"       # 其他
```

### 3.2 分类映射(单一规则表)

```python
_CATEGORIZE = [
    (lambda e: isinstance(e, TransportTimeoutError), ErrorCategory.TIMEOUT),
    (lambda e: isinstance(e, socket.timeout), ErrorCategory.TIMEOUT),
    (lambda e: isinstance(e, ProtocolFrameError), ErrorCategory.PROTOCOL),
    (lambda e: isinstance(e, DeviceError), ErrorCategory.DEVICE),
    (lambda e: isinstance(e, (ConnectionRefusedError, ConnectionResetError,
                              socket.gaierror)), ErrorCategory.TRANSPORT),
    (lambda e: isinstance(e, OSError), ErrorCategory.TRANSPORT),
    (lambda e: isinstance(e, TransportClosedError), ErrorCategory.TRANSPORT),
]
```

`_categorize_exception(exc) -> ErrorCategory` 助手内部按表短路。

### 3.3 code 提取

```python
def _extract_code(exc: BaseException) -> Optional[int]:
    if isinstance(exc, DeviceError):
        return exc.code
    if isinstance(exc, OSError):
        return exc.errno
    return None
```

### 3.4 新增 property

```python
class BaseClient:
    @property
    def last_error_category(self) -> Optional[ErrorCategory]: ...
```

### 3.5 写入点

| 位置 | 写入内容 |
|---|---|
| `connect()` 失败(`:122-125`) | category + code + last_error(str 同步) |
| `_after_connect()` 失败(`:137`) | 同上 |
| `disconnect()` 失败(`:166`) | 同上 |
| `close()` 失败(若有) | 同上 |
| `_execute` 读失败 `DeviceError`(`:531`) | category=DEVICE, code=exc.code |
| `_execute` 读失败 `OSError/Internal`(`:536`) | category=TRANSPORT 或 PROTOCOL, code=exc.errno 或 None |

| `_execute` 读成功(`:526`) | 三字段全清 None |

### 3.6 aio 镜像

两个新 property 转发到 `self._sync`。

### 3.7 README 示例

```python
ok, val = client.read_ushort("D100")
if not ok:
    cat = client.last_error_category
    code = client.last_error_code
    if cat is ErrorCategory.DEVICE and code == 0xC059:
        alert.warn("MC 地址越界")
```

## 四、P0-3 写前原值采集

### 4.1 API 表面

```python
class BaseClient:
    read_before_write: bool = False  # 类默认,实例可覆写
    _last_write_prev: Optional[Tuple[str, Any]] = None

    @property
    def last_write_previous(self) -> Optional[Tuple[str, Any]]:
        """开关打开后,记录最近一次 write_* 调用前的 (地址, 旧值)。
        未开启、写失败、读失败 → None(或保持上次值)"""
        return self._last_write_prev
```

### 4.2 行为

- `read_before_write = False`(默认)→ 完全等同 v0.33.0 行为,**零额外读线**
- `read_before_write = True` → 每个 `write_*` 调用前先 `read_*` 同地址;成功写入后把 `(addr, prev)` 存到 `last_write_previous`
- **读失败**:`write` 照常执行(写优先级高);`_last_write_prev` **不更新**(保留上次值或 None);不影响 `last_error`
- **写失败**:`_last_write_prev` 不更新
- **多类型覆盖**:`write_bool`/`write_short`/`write_ushort`/`write_long`/`write_ulong`/`write_float`/`write_double`/`write_string` 全部接入
- **`write_many` / `write_batch`**:开关开启时,每个点位前都先读,记录最后一次(若需全栈,调用方自维护)

### 4.3 实现路径

`base_client.py` 在 `_write` 抽象之上加 `_write_with_prev_capture` 包装:

```python
def _write_with_prev_capture(self, addr, value, write_callable):
    captured: bool = False
    prev: Any = None
    if self.read_before_write:
        try:
            ok, prev = self._read(addr)  # 通过 _read 抽象
            captured = ok  # 仅 read 成功才标记
        except (DeviceError, OSError, OmniPLCInternalError):
            captured = False  # 吞例外,不污染 last_error
    ok = write_callable()
    # 仅在 read 成功 + write 成功时才更新 prev 快照
    if ok and captured:
        self._last_write_prev = (addr, prev)
    return ok
```

各 `write_*` 方法体改为调用 `_write_with_prev_capture`。

### 4.4 aio 镜像

`read_before_write` 实例属性 + `last_write_previous` 只读 property,均转发到 `self._sync`。

### 4.5 README 示例

```python
client.read_before_write = True
client.write_ushort("D100", 42)
addr, prev = client.last_write_previous  # ("D100", <旧值>)
# 审计日志
logger.info("D100: %s -> 42", prev)

# 关闭后恢复默认行为(零额外读线)
client.read_before_write = False
```

## 六、明确不做(用户裁决)

| 不做项 | 原因 |
|---|---|
| `write_*(capture_previous=...)` 参数版 | 用户选"属性开关",非"参数开关" |
| `client.transaction()` 上下文管理器 | 增加所有 write 的隐式读线,违反尊重现场实时性原则;read+write 不原子 |
| `write_history` 环形历史 | 调用方自维护更灵活(用 `last_write_previous` 触发或自己写栈) |
| `compare_and_swap` 协议级 CAS 扩充 | 已在 D 方案留 backlog,本版不动 |
| `stats` 加"上次错误至今"字段 | stats 已有 timestamps,够用 |
| 异步原生 asyncio 重写 | 架构改造,留 v1.x(架构图 §3 自承) |
| ConnectionRefused/Reset/Timeout 三类细分 | 用户选 5 值粒度,够用;不细分子类 |
| `last_error_history: Deque` 错误环 | 调用方自维护;库只暴露 latest |
| 熔断器(连续 N 次失败短时拒绝) | 与退避功能重叠;退避已能控制风暴;留 backlog |

## 八、风险与回退

### 风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| `_next_connect_at` 浮点精度边界 | 低 | 低 | 单调时钟 + float,边界判定用 `<` |
| `reconnect_backoff=True` 默认打开,老用户感知到变化 | 中 | 低 | README 显著标注;`False` 一行恢复 |
| `read_before_write=True` 老用户误开 → 性能翻倍 | 低 | 中 | 默认 False;属性命名明示语义 |
| 错误 category 规则被新异常类型绕过 | 中 | 低 | 兜底 `UNKNOWN`;新增异常类型时同时更新规则表 |
| aio mirror 内省守卫测试失败 | 低 | 中 | 已为常规 property 写过;同步加 3 个转发即可 |

### 回退方案

- `reconnect_backoff=False` 一行恢复旧行为(完全 v0.33.0 等价)
- `read_before_write=False` 一行恢复旧行为
- `last_error` 字段未变,旧调用零感知
