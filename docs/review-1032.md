## 二、PDF 归档策略(★ 本报告最重要的结构性发现)

### 2.1 现状(亲验)

```
.gitignore:151-152
    # Mitsubishi copyrighted manuals stay local only
    docs/**/*.pdf

实测:git ls-files 'docs/**/*.pdf'  ->  0 个(被跟踪)
     磁盘 docs 下 *.pdf                -> 53 个
```

**即:`docs/protocol/` 下 13 个厂商目录的 **53 份 PDF 全部未被 git 跟踪**(全新 clone 里一个都没有)。

### 2.2 论证:这是"依据铁律"的执行性缺口

- 项目铁律要求协议实现"**就近注释页码级出处**",格式 = 「文档编号/名称 + 第几页 + 具体引用位置」;
- 但**页码级核对的唯一凭据(手册 PDF)不在版本库里** ⇒
  **从 clone 出发无法复核任何一条依据** —— 包括本轮 12 份台账里所有"手册实核"结论;
- **后果分层**:
  1. **审计可执行性**:新维护者/外部审计者拿到仓库后,所有 `依据:... 印刷页 N` 都**无从验证**;
  2. **结论可复现性**:本轮(以及 review-1024/1027/1029/1031)的"手册逐页核对"结论**依赖本机状态**;
  3. **风险敞口**:手册一旦本地丢失(换机/清理 `%TEMP%`/磁盘故障),依据链**不可恢复**。
- **注**:**`.gitignore` 注释只提 Mitsubishi**(“Mitsubishi copyrighted manuals stay local only”),
  而模式 `docs/**/*.pdf` 是**全局**的 —— 即**意图与效果不一致**:上汽/欧姆龙/ODVA 等
  非三菱手册**并非因该版权理由需要排除**,却被同一条规则一起忽略了。

### 2.3 定级与建议

- **定级 P1**(就"依据链的可执行性"而言)——它不是某族的功能缺陷,而是**全库依据纪律的执行底座**;
- **建议(需人工裁决)**:
  1. **明确策略**:是"全部手册本地留存(则必须提供替代凭据)"还是"仅三菱手册本地留存";
  2. 若为后者:`docs/**/*.pdf` 改为**按厂商目录**排除(仅 `docs/protocol/mitsubishi/**/*.pdf`),
     其余厂商手册入库;
  3. 若为前者:每条依据除页码外**须附可核片段**(如档案里内嵌算例字节/表格摘录),
     使"页码 → 事实"这一步**在库内闭合** —— EZSocket 档案的 §1-§11 正是这个形态
     (**它把帧面事实连字节样本一起写进了库内归档**,故其结论可复核);
  4. **登记**:在 `docs/protocol/README.md` 顶部写明"手册 PDF 为本地留存、不入库",
     并说明复核方式(clone 后如何取得)。
