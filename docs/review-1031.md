## 二、P1-1 BOOL 写数据段**少 1 字节**(亲验)

### 2.1 现状(亲验源码)

```python
# plc/omron/cip.py:144-152(标量 BOOL 写)
if cip_type == codec_cip.CIP_TYPE_BOOL:
    self._transact(
        codec_cip.build_tag_write(
            codec_cip.tag_type_path(parsed),
            cip_type,
            b"\x01" if flag else b"\x00",        # ← 只发 1 字节
        ),
        ...
# :154-164(DWORD 回退路径)
            cip_type, b"\x01" if flag else b"\x00",   # ← 同样 1 字节
```

`plc/ab/ab.py` 亦有一处同形(子代理指出)。

### 2.2 手册实核

**W506 §7-7-3 自印 p.7-91(PDF 387)**:布尔数据格式 = **Status + Forced 两个字节**,
**写时 Forced 填 0**。

### 2.3 影响与定级

- **后果**:标量与数组元素的 BOOL 写都可能被设备以 **0x13 `NOT_ENOUGH_DATA`** 拒;
- **定级 P1**:①有手册明文(依据完整);②后果是"合法写被拒"(响亮失败,非静默错值),
  但**BOOl 写是基础操作**,影响面大;
- **附带**:代码 docstring 引的「W506 §7-6-2」**章节号错**(实为 §7-7-3),
  且把问题只当作"BOOL **数组**"问题(标量同样受影响)。
- **修法**:两处载荷改 `b"\x00\x01" if flag else b"\x00\x00"`(Status + Forced),
  并订正章节号与影响面描述;AB 侧同形处一并核。

## 三、P1 候选(3.1~3.2)+ 撤回项(3.0)+ P2/P3 补(3.3~3.4)

### 3.0 ~~P1 候选~~ **【前提被手册原文推翻 → 本条撤回】**:BOOL 应答的 `Num of Element` 域

> **⚠ 2026-10-11 对抗验证 + 主会话复核:本节前提不成立**
>
> **W506 自印 7-90 §7-7-2 原文**:
> 「`UINT Num of Element (L)(H)` … **This field exists only in the parameters for the
> variable write service.**」
> ⇒ **该域只存在于写服务参数中,应答侧不含**;
> "含 `Num of Element`"的格式出现在 §7-7-4 讲**写侧指定元素数**的例外段。
>
> **结论**:**"读回应带该域"这一前提与手册原文冲突** ⇒ **P1 候选撤回**。
> 保留价值仅在于:`parse_tag_read_payload` 中"值域以元素数据开头"这一假设
> **值得在 docstring 写明** —— 因为它现在**有手册依据**(§7-7-2),不再是待核假设。
>
> 下列原始分析**保留备查**:其**代码路径亲验无误**,错的只是"固件会回该域"这一前提。

- **代码**(亲验):`parse_tag_read_payload`(`codec_cip.py:1271-1284`)对原子类型**只剥 2 字节**
  (`cip_type + 0x00`),返回 `payload[2:]` 作为"值字节",**不做任何元素数字段处理**;
  随后 `decode_values(data, cip_type, count)`(`:1501` 起)**按定长表**解码
  (BOOL 的 `size` 为 1)⇒ **把值域首字节当第一个元素**。
- ~~**手册**:W506 §7-7-4 自印 **p.7-92**(PDF 388)的 BOOL **数组元素**应答图示**含 `Num of Element`**~~
  **← 该条已被 §7-7-2 原文推翻(见上方警告框)**
- **后果**:若固件确实回 `… Status + Num of Element + 数据`,
  则代码会把 **`Num of Element` 的低字节当作 Status** 解码 ——
  **元素数 ≥ 1 时低字节为 0x01 ⇒ 恒判 TRUE** ⇒ **FALSE 读成 TRUE(静默假值)**;
  且 `len(data) >= size*count` 的校验**不会拦住**(多出的字节不触发不足判定)。
- **定级**:按"静默假值"形态本应 P1,但**触发取决于固件是否回该域**(手册图示与实际固件可能有别),
  故列为 **P1 候选 + 真机前置**(子代理已给出判据:抓一次 BOOL 数组元素读的应答,
  看值域是否带 `01 00` 前缀)。
- **修法**:`parse_tag_read_payload` 对 BOOL 增加"可选元素数域"的探测/按 `count` 交叉校验,
  或在 `decode_values` 前按 `len(data)` 与 `size*count` 的**关系**判定是否含前缀
  (`len(data) == size*count` → 无前缀;`> ` → 有前缀并校验元素数)。

### 3.1 STRING 类型码:手册 STRING=**0xD0**,而代码只认 0xA0

- **手册**:W506 §7-7-1 自印 **p.7-89** 明确 **STRING = 0xD0**、**0xA0 = Abbreviated STRUCT**;
- **代码**:读路径(继承 `_read_string`)**只接受 0xA0** → NJ 若按手册回 `0xD0`,
  `read_string` 直接 `ValueError`;
- **写路径**:按 Logix 的 `len(u32) + 字符` 回写,而 §7-7-3 **无 STRING 线上格式** →
  **有写坏变量的风险**;
- **披露状态**:已在 `review-1018 P2-6` 披露,但子代理建议**升 P1** 并列为**真机前置**项;
- **我的判定**:同意升 —— 理由是**写路径无手册依据**(不只是"读不认"),而写坏变量属静默错值形态。

### 3.2 `0x4E` 读-改-写:W506 **全文零命中**

- **手册**:§7-6 只列 **4C/4D**;§7-5-1 自印 p.7-48 对象表**无 Tag 对象** → **`0x4E` 无手册依据**;
- **代码**:位写与 BOOL 数组回退写走 0x4E 读-改-写(`_modify_word`/`_word_index_path`);
- **文档**:`docs/protocol-features.md` §6 却标「**位写 ✅**」——**无依据却标完成**;
- **定级 P1 候选**:①无手册依据;②文档把未核证能力标为 ✅ —— 与 review-1028 §6.2(KV MC)
  同一形态("账记了但没还")。
- **修法**:文档补「0x4E 为库内扩展/Logix 口径,欧姆龙侧待真机」;或在拿到正典前降级标注。

### 3.4 P3 补(子代理逐条)

`_write_string` 中命名为 `template_id` 的 2 字节在 W506 §7-7-4 自印 **7-93** 实为
「**结构的 CRC 值**」→ 数值口径一致、**命名误导**;
发起方厂商号 `0x1337` 的注释称"目标设备不校验"**无任何引用**;
`SendUnitData` 的 CPF timeout 填 `1`,而 Rockwell **p.20** 要求 SendUnitData 用 **0x0000**;
`architecture.md` 仍写"v1 显式拒绝字符串读写"与已实现的 NJ STRING 路径不符;
`protocol-features.md` 把批量读写成"继承 `Get_Attribute_List` 打包"(实为 `0x0A` Multiple Service Packet);
`VarAA.MemB[1][2]` 写法被拒,而 W506 §6-2-4 自印 **6-28** 明确 `array [2][3]` **或** `array [2,3]` 等价。
